## 1. Data Collection: Policy vs. Implementation

### 1.1 Data Actually Collected by cloud.js

| Data Point | How Collected | Where Stored |
|-----------|--------------|-------------|
| Email address | `submitCloudAuth()` via Firebase Auth `createUserWithEmailAndPassword` / `signInWithEmailAndPassword` | Firebase Auth |
| Firebase UID | Generated by Firebase Auth (anonymous or email) | Firebase Auth + Firestore `users` collection |
| Username / Display Name | From `save.username` or `save.playerId` | Firestore `users/{uid}` document |
| Anonymous status | `cloudState.user.isAnonymous` | Firestore `users/{uid}.isAnonymous` |
| Last seen timestamp | Server timestamp on each profile sync | Firestore `users/{uid}.lastSeenAt` |
| Full game save data | `exportSaveData()` called in `syncCloudSaveNow()` | Firestore `player_saves/{uid}/saves/latest` |
| Best tier and best wave | Extracted from save object | Firestore `player_saves/{uid}/saves/latest` |
| Sync reason | String tag (e.g., "manual", "queued", "bootstrap") | Firestore `player_saves/{uid}/saves/latest.syncReason` |
| Firebase web config | User-entered config JSON | `localStorage` key `core_surge_firebase_web_config_v1` |

## 3. Data Deletion

### 3.1 Policy Claim

Section 5.3 states users can request account deletion through in-game Settings or by emailing support@coresurge.game.

### 3.2 Implementation Check

- **In-game deletion button:** NOT IMPLEMENTED. cloud.js provides `signOutCloudSession()` (pauses cloud sync) and `clearCloudConfig()` (removes local Firebase config), but neither deletes the Firebase Auth account or Firestore data.
- **Firebase Auth account deletion API:** NOT CALLED anywhere in cloud.js. The Firebase client SDK method `user.delete()` is never invoked.
- **Firestore data deletion:** NOT IMPLEMENTED. No code deletes documents from `player_saves` or `users` collections.
- **Server-side deletion:** No Cloud Functions or admin SDK scripts exist to handle deletion requests.

**Gap: CRITICAL.** The privacy policy promises account deletion capability that does not exist in code. To comply, the implementation needs:
1. A "Delete Account" button in Settings that calls `firebase.auth().currentUser.delete()` and deletes associated Firestore documents
2. OR a documented manual process where support@coresurge.game handles deletion requests within the stated 30-day window

## 4. Offline / Local-Only Mode

### 4.1 Policy Coverage

The privacy policy does not explicitly describe what happens when a player uses the game in local-only mode (no Firebase config, no account).

### 4.2 Implementation Reality

When Firebase config is absent or the user has not signed in:
- `initFirebaseClient()` returns false, `cloudState.enabled` stays false
- No network requests are made to Firebase
- All data stays in `localStorage` only
- No third-party services receive any data
- `monetization.js` in web mode makes no network requests either

**Gap: MINOR.** The policy should include a statement that in offline/local-only mode, no personal data is transmitted to any server. This is a positive privacy feature worth documenting.

## 5. localStorage Usage

### 5.1 Not Mentioned in Policy

cloud.js stores the following in localStorage:
- `core_surge_firebase_web_config_v1` -- Firebase web config JSON (includes API key)
- `core_surge_cloud_auto_auth_disabled_v1` -- flag for paused cloud sync

monetization.js stores:
- `core_surge_revenuecat_config_v1` -- RevenueCat SDK keys
- `core_surge_store_receipts_v1` -- purchase receipt ledger

**Gap: MINOR.** The privacy policy does not mention client-side storage. While localStorage is not transmitted to third parties, it contains API keys and purchase records. Consider mentioning local storage in the policy for completeness.

---

## 7. Recommendations

1. **Immediate:** Revise `PRIVACY_POLICY.md` to separate "currently active" services from "planned future" services. Do not claim to collect data that is not actually collected.
2. **Before app store submission:** Implement account deletion (Firebase Auth `user.delete()` + Firestore document cleanup) or remove the self-service deletion claim and describe the manual email process.
3. **Before ad integration:** Update the privacy policy when AdMob is actually integrated, not before.
4. **Before analytics integration:** Same approach -- update the policy when Firebase Analytics and Crashlytics are added.
