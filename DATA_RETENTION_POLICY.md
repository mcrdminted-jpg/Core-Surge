# Data Retention Policy

**Core Surge: Endless Tower Defense**

**Effective Date:** May 24, 2026
**Last Updated:** May 24, 2026

This document describes what user data is stored by Core Surge: Endless Tower Defense, where it is stored, how long it is retained, and how users can request deletion.

---

## 1. On-Device Storage (localStorage)

### 1.1 Data Stored

| Data Item | Storage Key | Description |
|-----------|-------------|-------------|
| Game Save File | `tower_save_v8` | Complete local game state: tower loadout, card inventory, card levels, currencies (coins, gems), wave progress, rank progression, unlocked slots, settings preferences, tournament history |
| Firebase Configuration | Runtime only | Firebase project credentials for cloud connectivity (not persisted as user data) |
| RevenueCat Keys | Runtime only | Purchase verification tokens (managed by RevenueCat SDK) |

### 1.2 Retention Period

On-device localStorage data persists until:
- The user manually clears browser/app data
- The user uninstalls the application
- The user resets their game save via in-game settings

### 1.3 User Control

Users have full control over on-device data. Clearing browser data or uninstalling the app removes all local data permanently. A "Reset Save" option is available in the in-game Settings menu.

---

## 2. Firebase Firestore (Cloud Database)

### 2.1 Data Stored

| Collection/Document | Data Fields | Purpose |
|---------------------|-------------|---------|
| Player Profile | UID, display name, account creation date, last login, settings preferences | Account identification and personalization |
| Game Saves | Full save state (mirrors localStorage), timestamp of last sync | Cross-device save synchronization |
| Tournament Entries | Tournament ID, player UID, score, wave reached, deck used, submission timestamp | Tournament matchmaking and results |
| Purchase Receipts | Transaction ID, product ID, purchase date, platform, entitlement status | Purchase verification and entitlement management |

### 2.2 Retention Period

Cloud data is retained while the user's account remains active. "Active" means the user has not requested account deletion.

### 2.3 Inactive Accounts

Accounts with no login activity for 24 months may be flagged for review. Users will be notified via email (if provided) before any data is removed due to inactivity.

---

## 3. Firebase Authentication

### 3.1 Data Stored

| Data Field | Description |
|------------|-------------|
| Email Address | User-provided email for account login |
| User ID (UID) | Unique identifier generated by Firebase Auth |
| Account Metadata | Creation timestamp, last sign-in timestamp, authentication provider |
| Password Hash | Securely hashed password (managed entirely by Firebase; Developer has no access to plaintext passwords) |

### 3.2 Retention Period

Authentication data is retained while the account remains active. Upon account deletion, Firebase Auth records are removed as part of the deletion process.

---

## 4. Firebase Analytics

### 4.1 Data Stored

| Data Type | Description |
|-----------|-------------|
| Usage Events | Anonymized events such as: game_start, wave_completed, card_pulled, purchase_made, tournament_entered, ad_watched |
| Session Data | Session duration, session count, engagement time |
| Device Properties | Device model, OS version, app version, screen resolution (anonymized, not tied to individual identity) |
| User Properties | Player segment (new/returning), approximate geographic region |

### 4.2 Retention Period

Analytics data is retained per Google's default retention policy: **14 months** from the date of collection. After this period, event-level data is automatically deleted by Google. Aggregated reports may persist longer but contain no individually identifiable information.

### 4.3 User Control

Users can disable analytics data collection via the in-game Settings menu. When disabled, no new analytics events are sent. Previously collected data continues through its retention lifecycle.

---

## 5. Firebase Crashlytics

### 5.1 Data Stored

| Data Type | Description |
|-----------|-------------|
| Crash Reports | Stack traces, exception types, crash timestamps |
| Device Information | Device model, OS version, app version, available memory, disk space |
| Breadcrumb Logs | Recent user actions leading up to the crash (anonymized) |
| Session Identifier | Random session ID for grouping related crashes |

### 5.2 Retention Period

Crash report data is retained for **90 days** from the date of the crash event. After 90 days, individual crash reports are automatically purged. Aggregated crash statistics (crash-free rate, top crash types) may persist longer.

---

## 6. RevenueCat

### 6.1 Data Stored

| Data Type | Description |
|-----------|-------------|
| App User ID | Mapped to Firebase UID |
| Purchase History | All in-app purchase transactions, subscription status, renewal dates |
| Entitlements | Active entitlements (e.g., starter_pack, gems_small, monthly_vault) |
| Platform Data | Whether purchase was made on iOS or Android |

### 6.2 Retention Period

Purchase data is retained per RevenueCat's data retention policy. As purchase records are necessary for ongoing entitlement verification and tax/audit compliance, this data may be retained for the duration required by applicable law, even after account deletion.

---

## 7. Google AdMob

### 7.1 Data Stored

| Data Type | Description |
|-----------|-------------|
| Advertising ID | Device advertising identifier (IDFA on iOS, GAID on Android) |
| Ad Interactions | Impressions served, ads clicked, ad format, ad unit |
| Consent Status | Whether user has opted into or out of personalized advertising |

### 7.2 Retention Period

Ad interaction data is retained per Google's advertising data retention policies. Users can reset their advertising identifier through their device settings. Users can opt out of personalized ads through the in-game Settings menu.

---

## 8. Data Deletion Process

### 8.1 How to Request Deletion

Users can request deletion of their data through either:

1. **In-Game Settings:** Navigate to Settings > Account > Delete Account
2. **Email:** Send a deletion request to support@coresurge.game from the email address associated with the account

### 8.2 Deletion Timeline

Upon receiving a valid deletion request:

| Step | Timeline | Action |
|------|----------|--------|
| Acknowledgment | Within 3 business days | We confirm receipt of the deletion request |
| Account Deactivation | Within 7 days | Account is deactivated (login disabled, data hidden from other users) |
| Data Deletion | Within 30 days | Personal data is permanently deleted from Firestore and Firebase Auth |

### 8.3 Data That Survives Deletion

The following data is not deleted upon request, as it cannot be re-identified or is required by law:

| Data Type | Reason for Retention |
|-----------|---------------------|
| Anonymized Analytics | Data has already been anonymized and cannot be traced back to the individual user. Retained per Google's 14-month policy. |
| Purchase Receipts | Required for tax reporting, audit compliance, and fraud prevention. Retained for the period required by applicable tax law (typically 7 years). |
| Aggregated Statistics | Tournament results and leaderboard data may be retained in anonymized/aggregated form. |

### 8.4 Third-Party Data

Deletion requests are forwarded to relevant third-party services (Firebase, RevenueCat). Each service processes deletions according to their own policies and timelines. We cannot guarantee deletion timelines for third-party services but will make reasonable efforts to ensure compliance.

---

## 9. Data Backup and Recovery

### 9.1 Backups

Firestore data may be included in automated database backups. Backups are encrypted and retained for disaster recovery purposes. Deleted user data in active backups will be purged as backups are rotated (typically within 30 days of the backup cycle).

### 9.2 Recovery

Once data deletion is complete, it cannot be recovered. Users should export their data before requesting deletion if they wish to retain a copy.
